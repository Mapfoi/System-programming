## Теоретический материал

### Динамически подключаемые библиотеки (DLL)

**DLL** (Dynamic Link Library) — модуль с кодом и данными, который не запускается сам по себе, а подключается к уже работающему процессу. В Windows исполняемый файл **EXE** и **DLL** имеют общий формат **PE** (Portable Executable). При старте программы загрузчик ОС отображает EXE и перечисленные в таблице импорта DLL в виртуальное адресное пространство процесса.

Зачем нужны DLL:

- **Повторное использование** — одна копия `kernel32.dll` обслуживает множество процессов (с учётом ASLR и копирования при записи).
- **Обновление без пересборки EXE** — замена DLL (при совместимости экспорта).
- **Разделение на компоненты** — основная программа и плагины.

Экспортируемые функции помечаются в исходниках (например, `__declspec(dllexport)`) и попадают в **таблицу экспорта** PE-файла. Импортирующий EXE либо получает адреса на этапе **статической** линковки, либо запрашивает их во время выполнения через **GetProcAddress**.

### Статический и динамический импорт

| Способ | Когда резолвятся адреса | Типичные API |
|--------|-------------------------|--------------|
| **Статический** | При сборке EXE; загрузчик подтягивает DLL при старте по таблице импорта | `__declspec(dllimport)`, линковка с `.lib`-импортом |
| **Динамический (явный)** | В runtime, когда программа сама вызывает загрузчик | `LoadLibraryW` / `LoadLibraryA`, `GetProcAddress`, `FreeLibrary` |

При **статическом** импорте отсутствие DLL рядом с EXE или несовместимая версия часто приводит к ошибке уже при запуске. При **динамическом** программа может обработать отсутствие модуля (проверить результат `LoadLibrary`, показать сообщение).

Указатель на функцию, полученный через `GetProcAddress`, имеет тип, согласованный с вызывающей конвенцией (в этой работе — `__cdecl` для `MemReplaceStringA` и `WINAPI` / `stdcall` для точки входа удалённого потока).

### Точка входа DLL: DllMain

При загрузке и выгрузке модуля система вызывает **DllMain** с кодом причины:

- `DLL_PROCESS_ATTACH` — модуль впервые отображён в процесс;
- `DLL_PROCESS_DETACH` — модуль выгружается;
- `DLL_THREAD_ATTACH` / `DLL_THREAD_DETACH` — создание/завершение потоков (часто отключают через `DisableThreadLibraryCalls`).

**DllMain** — обязательная системная точка входа DLL: без корректного возврата `TRUE` загрузка модуля может не завершиться. В `memreplace_dll.c` там нет рабочей логики: при `LoadLibraryW` в мишени Windows вызывает `DllMain`, но **сама по себе загрузка не запускает** `MemReplaceStringA` и не меняет строку в Target.

Тяжёлые действия в `DllMain` при инжекции обычно избегают (loader lock, ограничения на вызовы API при attach). Поэтому замена строки вынесена в отдельный экспорт.

### MemReplaceRemoteEntry: зачем отдельная функция

Первый удалённый поток в **Lab5Inject** только выполняет **`LoadLibraryW`** — DLL появляется в адресном пространстве мишени. Чтобы **выполнить** код библиотеки (обход памяти и замену), нужен **второй** **`CreateRemoteThread`**.

Стартовая функция удалённого потока должна иметь вид:

```c
DWORD WINAPI ThreadProc(LPVOID lpParameter);  /* соглашение WINAPI (stdcall) */
```

**`MemReplaceStringA`** объявлена как **`__cdecl`** и принимает **два** аргумента (`search`, `replace`). Её нельзя использовать как прямой адрес для `CreateRemoteThread`: не совпадают calling convention и число параметров.

**`MemReplaceRemoteEntry`** — тонкая обёртка под удалённый поток:

- сигнатура **`DWORD WINAPI`** и один параметр `LPVOID` (здесь не используется);
- внутри вызывает `MemReplaceStringA(LAB5_SEARCH, LAB5_REPLACE)` — строки зашиты в DLL, не нужно записывать в память мишени указатели на `search`/`replace`;
- возвращает число замен (или ошибку) — инжектор читает результат через **`GetExitCodeThread`**.

Инжектор находит адрес **`MemReplaceRemoteEntry`** в Target (база модуля + смещение от локального `GetProcAddress`) и запускает второй удалённый поток. Код выполняется **в контексте Lab5Target**, поэтому `VirtualQuery` в `MemReplaceStringA` обходит память **мишени**, и меняется `g_text[]`.

| Функция | Роль в лабораторной |
|---------|---------------------|
| **DllMain** | модуль подключили к процессу (`LoadLibrary` / attach) |
| **MemReplaceRemoteEntry** | «кнопка» для второго `CreateRemoteThread` — запуск замены строки в мишени |
| **MemReplaceStringA** | общая логика поиска/замены; вызывается из Static, Dynamic и из `MemReplaceRemoteEntry` |

### Виртуальная память процесса в Windows

Каждый процесс видит своё **изолированное** 32- или 64-битное адресное пространство. Физическая RAM отображается **страницами** (обычно 4 KiB) с атрибутами доступа.

Полезные понятия:

- **Регион** — непрерывный диапазон адресов с одинаковыми свойствами (состояние, тип, защита).
- **MEM_COMMIT** — память передана процессу и может быть доступна (в отличие от зарезервированной `MEM_RESERVE`).
- **Защита страниц** — `PAGE_READONLY`, `PAGE_READWRITE`, `PAGE_EXECUTE_READ`, `PAGE_EXECUTE_READWRITE`, `PAGE_GUARD`, `PAGE_NOACCESS` и т.д.

Функция **VirtualQuery** (и **VirtualQueryEx** для чужого процесса) возвращает структуру **MEMORY_BASIC_INFORMATION**: базовый адрес региона, размер, состояние, защита. Обход всего пространства выполняется циклом: запрос → сдвиг указателя на `BaseAddress + RegionSize`.

Изменение содержимого защищённых страниц требует **VirtualProtect** (или **VirtualProtectEx**): временно выставляется `PAGE_READWRITE`, выполняется запись, восстанавливается прежняя маска. Это используется в `MemReplaceStringA` при замене найденной строки.

### Поиск и замена строки в памяти

Алгоритм лабораторной:

1. Задать границы пользовательского диапазона (`GetSystemInfo`).
2. Для каждого committed-региона, где разрешена запись, просканировать байты (`memcmp`).
3. При совпадении — `VirtualProtect` → `memcpy` → восстановление защиты.

Ограничение задания: **длины** искомой и замещающей строки **совпадают**, чтобы не сдвигать соседние данные и не ломать структуры, выровненные под фиксированный размер буфера.

Сканирование всего адресного пространства может находить **ложные совпадения** (случайная последовательность байт). В учебной связке «инжектор + Target» строка хранится в глобальном `g_text[]`, и замена в модуле Target предсказуема; в общем случае нужно сужать область поиска (конкретный модуль, известный адрес).

### Межпроцессное взаимодействие и права доступа

Чтобы изменять память или создавать потоки в другом процессе, нужен дескриптор с достаточными правами:

- **OpenProcess** с флагами вроде `PROCESS_VM_OPERATION`, `PROCESS_VM_WRITE`, `PROCESS_CREATE_THREAD`, `PROCESS_QUERY_INFORMATION` (или `PROCESS_ALL_ACCESS` в учебных примерах на своей машине).

Запись в адресное пространство мишени:

- **VirtualAllocEx** — выделить буфер под путь к DLL или параметры;
- **WriteProcessMemory** — скопировать байты из своего процесса.

Без прав администратора или при защите процесса (антивирус, Protected Process Light, другой пользователь) операции завершатся ошибкой `GetLastError`.

### Внедрение DLL через удалённый поток

Классическая схема **CreateRemoteThread + LoadLibrary**:

1. Открыть целевой процесс.
2. Записать в его память **полный путь** к DLL (Unicode — `LoadLibraryW`).
3. Получить адрес **LoadLibraryW** в **своём** процессе через `GetModuleHandle` + `GetProcAddress` на `kernel32.dll`.  
   На одной версии Windows для системных DLL базовые адреса в разных процессах часто совпадают (не гарантия навсегда, но для `kernel32` это стандартное допущение в учебных лабораторных).
4. **CreateRemoteThread** — в мишени стартует поток, который вызывает `LoadLibraryW(указатель_на_путь)`.
5. Дождаться завершения потока (**WaitForSingleObject**), освободить удалённый буфер.

После загрузки модуль живёт **в контексте мишени** (те же глобальные данные, куча и стек, что у Target), но замена строки начнётся только после второго потока — см. раздел **MemReplaceRemoteEntry** выше.

6. Узнать базу `memreplace.dll` в Target (**CreateToolhelp32Snapshot**, **Module32FirstW/NextW**).
7. В локальном процессе загрузить ту же DLL, взять адрес **`MemReplaceRemoteEntry`** через **GetProcAddress**, вычислить адрес в мишени:  
   `remote_fn = remote_base + (local_fn - local_base)`.
8. Второй **CreateRemoteThread** с начальным адресом `remote_fn`; дождаться завершения и прочитать код возврата потока.

### Сравнение программ лабораторной

| Программа | Процесс, где выполняется код DLL | Как подключается DLL |
|-----------|----------------------------------|----------------------|
| **Lab5Static** | свой | таблица импорта, линковка при сборке |
| **Lab5Dynamic** | свой | `LoadLibraryW` → `GetProcAddress` |
| **Lab5Inject** | **чужой** (Target) | удалённый `LoadLibraryW` + удалённый вызов экспорта |

**Lab5Dynamic** не принимает PID и **не** меняет память Target — только демонстрация явной загрузки в своём процессе. Для мишени используется **`Lab5Inject.exe <PID>`** (PID печатает **Lab5Target**).

### Замечания по безопасности и этике

Механизмы `OpenProcess`, запись в чужую память и удалённые потоки — базовые приёмы, применяемые отладчиками, профилировщиками и вредоносным ПО. Использовать их следует **только** на собственных учебных процессах в контролируемой среде. В production-системах срабатывают политики UAC, целостности кода и EDR.

## Как это реализовано в коде

**DLL.** Цикл `VirtualQuery` по адресному пространству **текущего** процесса; в committed-регионах с записью — поиск и замена с `VirtualProtect` / `memcpy`.

**Static / Dynamic.** Вызов `MemReplaceStringA` в локальном буфере; Dynamic дополнительно строит путь к `memreplace.dll` рядом с EXE.

**Inject.** Два удалённых потока: (1) `LoadLibraryW` — DLL в мишени, срабатывает только `DllMain`; (2) `MemReplaceRemoteEntry` — замена строки через `MemReplaceStringA` в памяти Target. Между ними — поиск базы модуля и перенос адреса экспорта по смещению.

## Сборка и запуск

Каталог сборки: `Lab 5 DLL/build` (CMake + Ninja/MinGW, см. CLion).

```text
cmake -S "Lab 5 DLL" -B "Lab 5 DLL/build"
cmake --build "Lab 5 DLL/build"
```

Запуск (из `build` или с указанием пути):

```text
Lab5Static.exe
Lab5Dynamic.exe
Lab5Target.exe
Lab5Inject.exe <PID_из_вывода_Target>
```

Порядок проверки инжекции: запустить **Lab5Target**, скопировать PID, запустить **Lab5Inject** с этим PID — в окне Target должна смениться строка.
