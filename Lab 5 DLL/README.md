# Лабораторная 5 — динамически загружаемая библиотека (DLL)

Открывать в **CLion**: File → Open → папка `Lab 5 DLL`.

## О чём эта работа

Windows-приложение обычно собирается из **модуля EXE** и подключаемых **DLL** — отдельных файлов с кодом и данными, которые загружаются в адресное пространство процесса. Одна и та же DLL может использоваться несколькими программами; код внутри неё выполняется **в контексте того процесса**, который её загрузил.

В лабораторной три способа **связать EXE с DLL** и один способ **подключить DLL к чужому процессу**:

1. **Статический импорт (на старте)** — линковщик знает имена функций заранее. При запуске EXE загрузчик подтягивает DLL и заполняет таблицу импорта; вызов выглядит как обычная функция, но реализация лежит в DLL.

2. **Динамический импорт (во время работы)** — программа сама вызывает `LoadLibraryW`, получает адрес экспорта через `GetProcAddress` и вызывает функцию по указателю. Так подключают плагины, опциональные модули или код, имя которого заранее не зашито в EXE.

3. **Внедрение удалённым потоком** — отдельная программа открывает **другой** процесс, заставляет его выполнить `LoadLibraryW` в своём адресном пространстве (`CreateRemoteThread`), затем вызывает экспорт DLL уже **внутри мишени**. Это классический приём для расширения чужого процесса своим кодом (в учебных целях — на своей же `Lab5Target`).

Общая **функция DLL** — пройти виртуальную память процесса, найти заданную **ASCII-строку** и заменить её другой **той же длины**. Так показывается связка «управление памятью» (`VirtualQuery`, права страниц, запись) и «код в DLL выполняется там, где DLL загружена».

## Задание

- DLL с поиском строки по виртуальной памяти и заменой (длины строк совпадают).
- EXE со **статическим** импортом DLL и указателем на экспорт.
- EXE с **динамическим** импортом (`LoadLibraryW`, `GetProcAddress`).
- EXE, который **внедряет** DLL в заданный процесс удалённым потоком и получает адрес функции DLL в этом процессе.

## Как это устроено

### DLL `memreplace.dll`

**`MemReplaceStringA`** — основная логика лабораторной:

- Берёт границы пользовательского адресного пространства через `GetSystemInfo`.
- Идёт по регионам с помощью `VirtualQuery`: интересуют только **переданные** (`MEM_COMMIT`) страницы, куда можно писать (через `VirtualProtect` при необходимости).
- В каждом подходящем регионе ищет подстроку `memcmp` и подменяет байты через `memcpy`.
- Возвращает число замен; в статистике — сколько регионов просмотрено и сколько байт записано.

Для **Static/Dynamic** сканируются регионы типа `MEM_PRIVATE` и `MEM_IMAGE` (куча, данные EXE и т.п.) — это и есть «память процесса» в практическом смысле задания.

**`MemReplaceRemoteEntry`** — одна функция с сигнатурой «точка входа потока» (`DWORD WINAPI …(LPVOID)`). Её адрес передаётся во **второй** `CreateRemoteThread` уже **в процессе-мишени**, после того как туда загрузили DLL. Внутри вызывается тот же поиск, но только по **`MEM_PRIVATE`** мишени (в демо — буфер `VirtualAlloc` в `Lab5Target`), чтобы не задевать лишние копии строк и образ самой `memreplace.dll`.

**`DllMain`** — формальная точка входа DLL; здесь пустая, потому что инициализация не нужна.

Демо-строки заданы в `memreplace_api.h`: `LAB5_DEMO_SEARCH` → `LAB5_DEMO_REPLACE` (одинаковая длина, без `\0` в подсчёте длины при сравнении — сравнивается ровно `strlen` символов).

### `Lab5Static.exe` — статический импорт

При сборке EXE **линкуется** с `memreplace.dll`: в коде объявлен `__declspec(dllimport)`, линковщик создаёт импорт.

Программа:

- Берёт указатель `fn = MemReplaceStringA` (это и есть «вернуть функцию DLL» из формулировки задания).
- Печатает адрес `fn`.
- Вызывает замену в своём буфере `g_demoBuffer` и показывает результат до/после.

Пока процесс жив, DLL уже загружена загрузчиком — отдельный `LoadLibrary` не нужен.

### `Lab5Dynamic.exe` — динамический импорт

Тот же сценарий замены, но связь с DLL программа устанавливает **сама**:

1. Собирает путь к `memreplace.dll` рядом с EXE.
2. `LoadLibraryW` — DLL попадает в **этот** процесс.
3. `GetProcAddress(module, "MemReplaceStringA")` — указатель `fn`.
4. Вызов через `fn`, затем `FreeLibrary`.

Так видно разницу: адрес функции появляется **явно**, только после загрузки модуля.

### `Lab5Target.exe` и `Lab5Inject.exe` — внедрение

**Target** — «жертва» для опыта: в цикле печатает PID и содержимое строки. Сама строка лежит в блоке **`VirtualAlloc`** (отдельный регион частной памяти), чтобы после внедрения было видно изменение в консоли.

**Inject** принимает **PID Target** (не путать с `Lab5Dynamic` — у него аргументов нет, он не трогает чужие процессы).

Последовательность:

1. **`OpenProcess`** — дескриптор мишени с правами на создание потока и работу с её памятью.
2. **Загрузка DLL в мишень:** в адресном пространстве Target выделяется память под **широкий путь** к DLL (`VirtualAllocEx`), путь копируется (`WriteProcessMemory`), создаётся **`CreateRemoteThread`**, который вызывает **`LoadLibraryW`** из `kernel32.dll`. Поток мишени выполняет загрузку **у себя** — DLL оказывается в её списке модулей.
3. **Адрес экспорта в мишени:** инжектор загружает ту же DLL **локально**, находит `MemReplaceRemoteEntry` через `GetProcAddress`, вычисляет **смещение** от базы модуля и прибавляет его к **базе DLL в Target** (модуль ищется снимком процесса — полный 64-битный адрес). В консоли печатается этот адрес — второй пункт задания («вернуть функцию DLL») для **чужого** процесса.
4. **Вызов кода в мишени:** снова `VirtualAllocEx` / `WriteProcessMemory` (блок `MemReplaceParams` — канал параметров для удалённого потока), второй **`CreateRemoteThread`** на `MemReplaceRemoteEntry`. Код DLL выполняется **в Target** и меняет строку в его памяти.

```text
Lab5Inject                          Lab5Target
    |                                    |
    |  remote thread: LoadLibraryW       |
    |----------------------------------->|  memreplace.dll в процессе Target
    |                                    |
    |  remote thread: MemReplaceRemoteEntry
    |----------------------------------->|  g_lab5Needle → "Lab5NewString!!"
```

## Сборка

1. Toolchain: MinGW-w64 или MSVC (CLion: bundled MinGW + CMake).
2. Reload CMake → Build `all`.
3. Артефакты: `build/` или `cmake-build-*` — `memreplace.dll` и все `.exe`.

```text
cmake -S "Lab 5 DLL" -B "Lab 5 DLL/build" -G Ninja
cmake --build "Lab 5 DLL/build"
```

## Проверка

```text
Lab5Static.exe
Lab5Dynamic.exe
Lab5Target.exe
Lab5Inject.exe <PID_из_Target>
```

После инъекции в окне Target строка должна стать `Lab5NewString!!`.
