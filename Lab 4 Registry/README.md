# Лабораторная 4 — реестр (WinAPI / C)

Открывать в **CLion**: File - Open - папка `Lab 4 Registry` (подхватит `CMakeLists.txt`).

## Задание

- Добавление, изменение и удаление ключа `HKEY_CURRENT_USER\Software\Lab4Registry`
- Чтение флагов доступа к своему ключу и попытка прочитать их у `HKEY_LOCAL_MACHINE\SAM`
- Отслеживание изменения ключа
- Размер файлов реестра на диске

## Сборка в CLion

1. Toolchain: MinGW-w64 или MSVC
2. Reload CMake Project
3. Run configuration: `Lab4Registry`

## Что делает программа

Консольная программа один раз проходит все пункты лабораторной: считает вес файлов реестра, создаёт свой ключ, меняет в нём значение, читает флаги доступа, ждёт изменение ключа и в конце удаляет всё, что создала. Чужие разделы она только открывает на чтение прав, без записи.

## Описание кода (`main.c`)

### Заголовок и константы

`windows.h` подключает функции реестра из **Advapi32.dll**. `fcntl.h` и `io.h` нужны только для широкого вывода в консоль.

Комментарии в начале файла — ответы на вопросы лабораторной: зачем нужен реестр, чем Windows отличается от других ОС, какие есть главные разделы и короткие пути, чем реестр ещё правят (`regedit.exe`, `reg.exe`, PowerShell), что вес реестра — это размер его файлов на диске.

`kKey` и `kValue` — путь и имя, с которыми работает программа. Путь относительный: его всегда открывают от раздела `HKEY_CURRENT_USER`, поэтому полный ключ — `HKEY_CURRENT_USER\Software\Lab4Registry`. Запись туда не требует прав администратора.

### `PrintResult` и `PrintMegabytes`

`PrintResult` переводит код возврата WinAPI в понятную строку. Ноль (`ERROR_SUCCESS`) означает успех — печатается только текст («ключ создан»). Любой другой код выводится как «ошибка» с номером.

`PrintMegabytes` делит размер в байтах на `1024 × 1024` и печатает мегабайты с двумя знаками после запятой.

### `PrintRegistrySize` — вес реестра

Реестр на диске хранится в файлах (в учебнике их называют ульями). Функция читает размер каждого файла через `GetFileAttributesExW`, не открывая файл на запись.

- `SystemRoot` — каталог Windows (обычно `C:\WINDOWS`). От него собираются пять файлов раздела **HKEY_LOCAL_MACHINE**: `SYSTEM`, `SOFTWARE`, `SAM`, `SECURITY`, `DEFAULT`.
- `USERPROFILE` — каталог текущего пользователя. Файл `NTUSER.DAT` в нём — реестр пользователя, короткий путь **HKEY_CURRENT_USER**.

Размер файла приходит двумя 32-битными полями (`nFileSizeHigh` и `nFileSizeLow`); их склеивают в одно 64-битное число. Если доступ запрещён, печатается «нет доступа», файл в сумму не входит. В конце — общий вес в мегабайтах по тем файлам, которые удалось прочитать.

### `PrintMask` — расшифровка маски доступа

У каждой записи в списке доступа есть число-маска. `PrintMask` проверяет отдельные биты и печатает, какие права в маске включены: чтение и запись значения, создание подраздела, перечень подразделов, слежение за изменениями, чтение и изменение прав, смена владельца. Сначала выводится шестнадцатеричное значение (`0x........`), затем список прав через запятую.

### `PrintAccess` — флаги доступа к ключу

1. `RegOpenKeyExW` открывает ключ с правом `READ_CONTROL` — этого хватает, чтобы прочитать список доступа (DACL), но не менять значения в ключе.
2. `RegGetKeySecurity` с флагом `DACL_SECURITY_INFORMATION` запрашивает этот список. Размер заранее неизвестен: первый вызов идёт в буфер на 256 байт; при `ERROR_INSUFFICIENT_BUFFER` выделяется буфер нужного размера через `malloc`, вызов повторяется.
3. Дескриптор ключа после чтения закрывается — он больше не нужен.
4. `GetSecurityDescriptorDacl` извлекает список доступа; `GetAclInformation` сообщает число записей; `GetAce` перебирает записи. Для каждой печатается «разрешение» или «запрет» и маска через `PrintMask`.

Вызов делается для своего ключа и для `HKEY_LOCAL_MACHINE\SAM`. На `SAM` открытие или чтение прав может не пройти — это нормальная «попытка» для чужого защищённого раздела.

### `main` — создание и изменение

`_setmode(_fileno(stdout), _O_U16TEXT)` переводит стандартный вывод в режим UTF-16, иначе русский текст из `wprintf` в консоли отображается неверно.

**Создание ключа.** `RegCreateKeyExW` создаёт ключ или открывает уже существующий. Маска `KEY_READ | KEY_WRITE | KEY_NOTIFY` запрашивается сразу: тем же дескриптором потом читают и пишут значение и ждут изменения.

**Значение.** `RegSetValueExW` дважды записывает строку `REG_SZ` с именем `Sample`: сначала «добавлено», затем «изменено» (второй вызов заменяет текст). Длина передаётся в байтах и включает завершающий нуль wide-символа.

**Чтение.** `RegQueryValueExW` читает значение обратно — в выводе должно быть «изменено».

### Слежение за ключом

1. `CreateEventW` создаёт объект-событие — сигнал «ключ изменился».
2. `RegNotifyChangeKeyValue` ставит асинхронное ожидание: при изменении значения (`REG_NOTIFY_CHANGE_LAST_SET`) система переводит событие в сигнальное состояние. Ожидание включают **до** записи нового значения.
3. Ещё один `RegSetValueExW` меняет значение — это и есть изменение, на которое подписана функция.
4. `WaitForSingleObject` ждёт событие до 5 секунд. `WAIT_OBJECT_0` означает, что изменение зафиксировано.

### Удаление

`RegDeleteValueW` удаляет значение `Sample`. `RegCloseKey` закрывает дескриптор — удалять ключ с открытым дескриптором нельзя. `RegDeleteKeyW` удаляет пустой ключ по пути от `HKEY_CURRENT_USER`. `CloseHandle` освобождает событие. `fflush(stdout)` сбрасывает вывод до `system("pause")`, чтобы сообщение «нажмите любую клавишу» не перемешивалось с текстом программы.
